# Linsor AI 后端工程规范

## API 契约

- 全局前缀为 `/api`。
- 普通成功响应统一为 `{ success, code, message, data? }`。
- SSE、文件下载等流式响应明确绕过普通响应包装。
- JSON DTO 使用 `class-validator`；全局 `ValidationPipe` 启用 `transform` 和 `whitelist`。
- 参数错误统一转换为 `ErrorCode.PARAM_ERROR`。

## 异常处理

- 可预期业务错误抛出 `BusinessException`。
- 业务错误必须使用统一 `ErrorCode`，不得由 Controller 拼装任意错误结构。
- 下游数据库、模型、邮件和存储错误在业务边界保留原因并转换为稳定语义。
- `AllExceptionsFilter` 是最终异常出口。

## 日志与追踪

- 使用 Winston 作为全局 Logger。
- 每个请求绑定 `requestId`，响应和日志应保持同一标识。
- 日志记录上下文和必要标识，不记录密码、Token、API Key 或完整敏感正文。
- Agent 执行细节写入 Run/Step 记录，系统管理操作写入审计日志。

## 鉴权与权限

- 普通用户接口使用 JWT `AuthGuard`。
- 管理端使用独立管理员认证。
- Controller 通过 `@CurrentUser` 获取可信用户信息。
- 知识库资源操作使用 `@KbPermission(...)` 与 `KbPermissionGuard`。
- Service 仍需校验资源归属、版本和幂等条件，不能只依赖前端隐藏按钮。

## 数据访问

- 统一注入 `PrismaService`。
- 多步写操作按一致性需要使用事务。
- BigInt 在 API 边界序列化为字符串。
- Schema 变更必须通过 Prisma migration。
- 不将 Qdrant 或 Elasticsearch 当作业务事实来源。

## 配置

- 配置通过 `ConfigModule` 和 Joi 在启动阶段校验。
- 新增配置时同步更新 `.env.example` 和校验规则。
- 密钥不得提供不安全默认值。
- `VITE_` 环境变量会进入客户端，不得存放服务端秘密。

## 模块开发

```text
module/
├── *.module.ts
├── *.controller.ts
├── *.service.ts
├── dto/
├── interfaces/
└── *.spec.ts
```

- Controller 保持薄层，只处理协议转换和调用 Service。
- DTO 表达外部输入，Interface 表达内部数据结构。
- 复杂流程由专用编排 Service 组织。
- 队列任务必须可重试、可识别旧版本并具备明确失败状态。
