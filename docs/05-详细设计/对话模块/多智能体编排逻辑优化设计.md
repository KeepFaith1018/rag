# 多智能体编排逻辑优化设计

## 1. 问题背景

当前 `MultiAgentOrchestratorService` 的状态图编排存在以下缺陷：

### 1.1 路由跳过导致 decompose 绕过

**问题**：`shouldRewrite` 对 `fact_lookup` 意图返回 `skip_rewrite`，直接进入 `retrieve_prep`，跳过了 `shouldDecompose` 检查。

```typescript
// 当前实现
function shouldRewrite(state: AgentState): 'rewrite' | 'skip_rewrite' {
  if (state.routedPlan?.intent === 'fact_lookup') return 'skip_rewrite';
  // ...
}
```

**后果**：即使 `routedPlan.needDecomposition === true`，compound fact lookup 问题也无法被拆解。

### 1.2 验证结果无后续处理

**问题**：fact check 和 completeness check 返回后，若 `needRevise === true` 或 `needSupplement === true`，系统只记录结果，不触发重试。

### 1.3 verify 阶段不在状态图中

**问题**：verify（fact_check + completeness_check）是在 `streamRun` 方法中直接调用的，不在状态图内，无法实现基于验证结果的条件分支。

### 1.4 partial 相关性不重试

**问题**：`shouldRetryOrContinue` 只处理 `not_relevant`，`partial` 直接 continue。

### 1.5 回退计数器语义混乱

**问题**：
- verify 失败触发的回退与相关性回退混用同一个计数器
- rewrite 失败时 fallbackCount 仍 +1

## 2. 优化方案

### 2.1 状态图优化

#### 优化后流程图

```
__start__
    │
    ▼
 route
    │
    ▼
[shouldRewrite] ──→ rewrite ──→ [shouldDecompose] ──→ decompose
    │ skip_rewrite           ↓ skip_decompose            │
    │                       └────────────────────┬───────┘
    ▼                                             ▼
retrieve_prep ←────────────────────────────────────┘
    │
    ▼
  tools
    │
    ▼
relevance_check
    │
    ▼
[shouldRetryOrContinue] ──→ rewrite (partial/not_relevant 回退)
    │ continue
    ▼
[shouldProceedToVerify] ──→ verify ──→ [shouldRevise] ──→ rewrite
    │ finalize                              │ no_revisions
    ▼                                         ▼
 __end__                                    __end__
```

#### 新增节点

| 节点 | 职责 |
|------|------|
| `verify` | 并行执行 fact_check + completeness_check |
| `finalize` | 标记流程结束（用于简单查询跳过 verify） |

#### 条件边变更

| 条件边 | 变更 |
|--------|------|
| `shouldRewrite` | `fact_lookup` 意图也进入 rewrite |
| `shouldRetryOrContinue` | 支持 `partial` 触发一次回退 |
| `shouldProceedToVerify` | 新增：判断是否需要 verify |
| `shouldRevise` | 新增：判断验证失败是否回退 |

### 2.2 条件边函数修改

#### shouldRewrite

```typescript
function shouldRewrite(state: AgentState): 'rewrite' | 'skip_rewrite' {
  // 只有 greeting 才完全跳过 planning
  if (state.routedPlan?.intent === 'greeting') return 'skip_rewrite';
  // 其余意图均进入 rewrite，由 shouldDecompose 判断是否拆解
  return 'rewrite';
}
```

#### shouldRetryOrContinue

```typescript
function shouldRetryOrContinue(state: AgentState): 'rewrite' | 'continue' {
  if (state.relevanceVerdict === 'not_relevant') {
    return state.fallbackCount < MAX_FALLBACK ? 'rewrite' : 'continue';
  }
  if (state.relevanceVerdict === 'partial') {
    return !state.pendingSupplement && state.fallbackCount < MAX_FALLBACK
      ? 'rewrite'
      : 'continue';
  }
  return 'continue';
}
```

#### shouldProceedToVerify（新增）

```typescript
function shouldProceedToVerify(state: AgentState): 'verify' | 'finalize' {
  // 无检索结果或完全不相关 → 直接结束
  if (!state.rerankedHits.length || state.relevanceVerdict === 'not_relevant') {
    return 'finalize';
  }
  // 简单查询跳过 verify
  const intent = state.routedPlan?.intent;
  if (intent === 'fact_lookup' || intent === 'greeting') {
    return 'finalize';
  }
  // 复杂查询 → verify
  return 'verify';
}
```

#### shouldRevise（新增）

```typescript
function shouldRevise(state: AgentState): 'rewrite' | 'no_revisions' {
  const needRevise = state.factCheckResult?.needRevise === true;
  const needSupplement = state.completenessResult?.needSupplement === true;
  if (needRevise || needSupplement) return 'rewrite';
  return 'no_revisions';
}
```

### 2.3 节点函数修改

#### rewriteQueryNode — 区分触发来源

```typescript
async function rewriteQueryNode(
  state: AgentState,
  chatModelService: ChatModelService,
  runId: string,
  traceService: AgentTraceService,
): Promise<Partial<AgentState>> {
  // 区分是 verify 触发的重试还是相关性触发的回退
  const isReviseRetry = state.pendingRevise === true;
  const round = state.fallbackCount + 1;

  console.log(
    `[Orchestrator] ✏️ 查询改写中... ${
      isReviseRetry ? '(verify 重试，不计入回退)' : `(第 ${round} 轮回退)`
    }`,
  );

  // ... 模型调用逻辑 ...

  return {
    rewrittenQueries: queries,
    // verify 触发的重试不消耗回退次数
    fallbackCount: isReviseRetry ? state.fallbackCount : state.fallbackCount + 1,
    pendingRevise: false,  // 清除标记
    currentPhase: 'planning',
  };
}
```

#### verifyNode（新增）

```typescript
async function verifyNode(
  state: AgentState,
  chatModelService: ChatModelService,
  runId: string,
  traceService: AgentTraceService,
): Promise<Partial<AgentState>> {
  if (!state.draftAnswer || !state.rerankedHits.length) {
    return { currentPhase: 'verifying' };
  }

  console.log('[Orchestrator] 🔎 并行质量校验中...');

  const [factResult, completenessResult] = await Promise.all([
    factCheckNode(state, chatModelService, runId, traceService),
    completenessCheckNode(state, chatModelService, runId, traceService),
  ]);

  return {
    ...factResult,
    ...completenessResult,
    currentPhase: 'verifying',
  };
}
```

#### pendingRevise 的使用

- **设置时机**：`shouldRevise` 返回 `'rewrite'` 时
- **检查位置**：`rewriteQueryNode` 入口
- **清除时机**：成功完成 rewrite 后

## 3. 分层回退策略

遵循分层策略，区分**网络/超时错误**与**代码 bug**：

| 节点 | 错误类型 | 处理策略 |
|------|---------|---------|
| `routeQueryNode` | 网络超时 | 重试 1 次，再失败抛异常 |
| `routeQueryNode` | 输出格式错误 | 直接抛异常（代码 bug） |
| `rewriteQueryNode` | 网络超时 | 重试 1 次，再失败降级用原始查询 |
| `rewriteQueryNode` | 输出格式错误 | 直接抛异常 |
| `decomposeNode` | 网络超时 | 重试 1 次，再失败跳过拆解 |
| `decomposeNode` | 输出格式错误 | 直接抛异常 |
| `factCheckNode` | 任意错误 | 降级：标记 low risk 继续 |
| `completenessCheckNode` | 任意错误 | 降级：标记不需补充继续 |
| `relevanceCheckNode` | 任意错误 | 降级：fallback 为 partial |

**原则**：
- **核心决策节点**（route）：网络错误可重试，格式错误必须抛
- **质量增强节点**（fact_check, completeness_check）：错误可降级，不阻断流程
- **降级行为必须记录日志**，便于排查

## 4. 状态图定义变更

### 4.1 AgentStateAnnotation

`pendingRevise` 字段正式启用：

```typescript
const AgentStateAnnotation = Annotation.Root({
  // ... 现有字段 ...
  pendingRevise: Annotation<boolean>(),  // verify 失败触发的回退标记
});
```

### 4.2 图构建

```typescript
const graph = new StateGraph(AgentStateAnnotation)
  .addNode('route', (s) => routeQueryNode(s, chatModelService, runId, agentTraceService))
  .addNode('rewrite', (s) => rewriteQueryNode(s, chatModelService, runId, agentTraceService))
  .addNode('decompose', (s) => decomposeNode(s, chatModelService, runId, agentTraceService))
  .addNode('retrieve_prep', () => ({ currentPhase: 'retrieving' }))
  .addNode('tools', async (s) => { /* 检索逻辑 */ })
  .addNode('relevance_check', (s) => relevanceCheckNode(s, chatModelService, runId, agentTraceService))
  .addNode('verify', (s) => verifyNode(s, chatModelService, runId, agentTraceService))
  .addNode('finalize', (s) => ({ currentPhase: 'done' }))
  // 边定义
  .addEdge('__start__', 'route')
  .addConditionalEdges('route', shouldRewrite, { rewrite: 'rewrite', skip_rewrite: 'retrieve_prep' })
  .addConditionalEdges('rewrite', shouldDecompose, { decompose: 'decompose', skip_decompose: 'retrieve_prep' })
  .addEdge('decompose', 'retrieve_prep')
  .addEdge('retrieve_prep', 'tools')
  .addEdge('tools', 'relevance_check')
  .addConditionalEdges('relevance_check', shouldRetryOrContinue, { rewrite: 'rewrite', continue: 'proceed_to_verify' })
  .addConditionalEdges('proceed_to_verify', shouldProceedToVerify, { verify: 'verify', finalize: 'finalize' })
  .addConditionalEdges('verify', shouldRevise, { rewrite: 'rewrite', no_revisions: 'finalize' })
  .addEdge('finalize', '__end__')
  .compile();
```

## 7. 风险与注意事项

1. **verify 纳入状态图后**，图执行变为同步，需确认流式输出不受影响
2. **pendingRevise 的生命周期**需严格管理，避免状态残留
3. **回退次数限制**（MAX_FALLBACK=2）对 verify 重试和相关性重试均生效
