# Kinetic Blueprint 设计系统

Kinetic Blueprint 是 Linsor AI 的视觉和交互规范。设计目标是让复杂的知识库、检索和 Agent 状态清晰可读，同时保持轻量、克制和一致。

## 设计原则

- 信息优先：层级通过留白、字号、色彩和表面区分，不依赖过度装饰。
- 状态可见：上传、检索、生成、错误和权限状态必须有明确反馈。
- 渐进呈现：复杂 Agent 步骤和引用细节按需展开。
- 一致交互：相同动作使用相同组件、位置和反馈语义。
- 明暗主题：所有颜色和高亮都需要在两种主题下可读。

## 色彩

- 使用语义 Token 表达背景、表面、边框、主文本、次文本和品牌色。
- 成功、警告、错误和处理中状态使用独立语义色。
- 不在业务组件中散落无法复用的硬编码颜色。
- 品牌色用于关键动作和焦点，不用于大面积背景。

## 字体与排版

- 正文使用 Inter。
- 标题和强调区域可使用 Space Grotesk。
- 正文保持舒适行高，长答案限制阅读宽度。
- 代码、表格和引用需要与正文形成清晰层级。

## 表面与层级

- 页面背景、主内容面板、浮层和弹窗形成稳定的表面层级。
- 边框和阴影应服务于分组，不同时叠加过强效果。
- 圆角、间距和高度使用统一尺度。

## 组件规范

### 按钮

- 主按钮只用于页面主要动作。
- 危险操作使用明确危险语义，并在不可逆时二次确认。
- 加载状态禁止重复提交。

### 输入

- 标签、帮助文本、校验信息和禁用原因清晰可见。
- 搜索、Prompt 和普通表单输入保持用途差异。

### 卡片与列表

- 知识库、文档和会话列表使用一致的选中、悬停和操作区行为。
- 权限不足时隐藏或禁用操作，但不得以此替代后端校验。

### AI 消息

- 流式内容保持布局稳定。
- 代码块提供语言、复制和主题适配。
- 引用可以定位到文档来源。
- Agent 步骤默认简洁，允许查看检索和工具详情。

### 上传

- 区分计算哈希、上传分片、合并、文档处理和失败状态。
- 暂停、重试和取消必须有明确结果。

## 可访问性

- 交互元素支持键盘焦点。
- 文本和背景满足可读对比度。
- 图标不能作为唯一状态信息。
- 动效尊重减少动态效果的系统偏好。

## 维护规则

设计 Token 和通用组件实现位于 `apps/web/src`。新增视觉模式前优先扩展现有 Token 和组件，不在页面局部建立第二套设计语言。
