# 对话模块详细设计文档

## 1. 模块概述

对话模块 (`chat`) 是 Linsor AI 系统的核心业务模块，负责处理用户与 AI 之间的对话交互。模块支持两种对话模式：

- **Chat Mode（聊天模式）**：简单的 LLM 对话，使用系统提示词
- **RAG Mode（RAG 模式）**：智能体编排的 RAG 工作流，实现知识库问答

**入口文件**：`apps/server/src/modules/chat/chat.controller.ts`

## 4. 核心服务详解

### 4.1 ChatStreamService (`services/chat-stream.service.ts`)

**依赖注入**：
```typescript
ChatSessionService,    // 会话所有权校验
ChatMessageService,     // 消息持久化
ChatModelService,       // LLM 模型访问
KbPermissionService,   // 知识库授权
CitationService,       // 引用持久化
MultiAgentOrchestratorService  // RAG 工作流编排
```

**`streamChat()` 方法流程**：

```
1. 校验会话所有权
   └── chatSessionService.assertSessionOwnership(userId, sessionId)

2. 获取模型名称
   └── chatModelService.getDefaultModelName()

3. 生成 traceId（UUID）

4. 根据 chatMode 分支：
   ┌─ RAG Mode（chatMode === 'rag' && selectedKbIds?.length）
   │   └── streamRagMode()
   │       a. KbPermissionService.authorizeMany() 授权知识库
   │       b. ChatMessageService.createUserMessage() 持久化用户消息
   │       c. ChatMessageService.createAssistantPlaceholder() 创建流式占位
   │       d. orchestrator.streamRun() 执行 RAG 工作流
   │
   └─ Chat Mode
       └── streamChatMode()
           a. 创建流式 LLM 模型（temperature 0.7）
           b. 持久化用户消息
           c. 创建助手占位
           d. 构建消息：[SystemMessage(系统提示), HumanMessage(用户消息)]
           e. model.stream() 流式输出，包装为 toUIMessageStream()
           f. 完成/中断/错误时 finalize 或标记 aborted
```

**Chat Mode 系统提示词**：
```
你是 Linsor AI（灵索智能）的智能助手，基于知识库为用户提供专业、准确的问答服务。
回答应准确、完整，基于上下文给出有用信息
若问题涉及特定知识库内容但当前未检索到上下文，如实告知用户
使用中文回答
```

### 4.4 MultiAgentOrchestratorService (`services/multi-agent-orchestrator.service.ts`)

**这是 RAG 模式的核心编排引擎**，基于 LangGraph 的 `StateGraph` 实现。

#### 4.4.1 AgentStateAnnotation 状态图

```typescript
{
  sessionId: string
  userId: number
  originalQuery: string           // 用户原始问题
  selectedKbIds: string[]        // 用户选择的知识库 IDs
  resolvedKbIds: string[]        // 解析后的（已授权的）知识库 IDs
  routedPlan: RoutedQueryPlan | null   // 路由器输出
  rewrittenQueries: string[]     // 重写后的查询
  decomposedQuestions: DecomposeOutput | null  // 分解结果
  rerankedHits: RerankedHit[]    // 检索结果
  draftAnswer: string            // 生成的答案
  factCheckResult: FactCheckResult | null
  completenessResult: CompletenessCheckResult | null
  fallbackCount: number          // 重试计数器（最多 2 次）
  currentPhase: string            // 'planning' | 'retrieving' | 'verifying'
  relevanceVerdict: 'relevant' | 'partial' | 'not_relevant' | null
  pendingSupplement: boolean      // 是否需要补充
  pendingRevise: boolean          // 是否需要修订
}
```

#### 4.4.2 节点函数（Node Functions）

每个节点对应一次 LLM 调用，使用结构化输出：

| 节点 | Agent | 用途 | 失败策略 |
|------|-------|------|----------|
| `routeQueryNode` | Router | 意图分类 | 抛出异常 |
| `rewriteQueryNode` | Rewriter | 查询扩展（1-3 个查询） | 使用原始查询 |
| `decomposeNode` | Decomposer | 拆分为子问题 | 跳过分解 |
| `relevanceCheckNode` | Verifier | 检查检索质量 | 设为 `partial` verdict |
| `factCheckNode` | Verifier | 事实校验 | 假设低风险 |
| `completenessCheckNode` | Verifier | 覆盖度检查 | 跳过 |

#### 4.4.3 条件边（Conditional Edges）

```typescript
shouldRewrite     // 仅对 'compare_analysis' 和 'research_or_open_world' 意图重写
shouldDecompose   // 基于 routedPlan.needDecomposition
shouldVerify      // 仅对复杂查询验证（compare_analysis, research_or_open_world）
shouldRetryOrContinue  // 当 verdict === 'not_relevant' 且 fallbackCount < 2 时重试
```

#### 4.4.4 预生成图流程（Pre-generation Graph）

```
__start__
    │
    ▼
routeQuery
    │
    ├─── [shouldRewrite] ──► rewriteQuery ──► decomposeNode
    │                         (skip_rewrite)
    │
    ├─── [shouldDecompose] ──► decomposeNode
    │                         (skip_decompose)
    │
    ▼
retrieve_prep ──► [tools: SearchKnowledgeBaseTool]
    │
    ▼
relevance_check
    │
    ├─── [shouldRetryOrContinue] ──► rewriteQuery
    │                                (__end__)
    │
    ▼
[继续到写作阶段]
```

#### 4.4.5 `streamRun()` 方法

- 使用 AI SDK 的 `createUIMessageStream()`
- 通过 `writer.write()` 发送自定义事件：

| 事件 | 内容 |
|------|------|
| `data-agent-status` | 阶段变化（planning, retrieving, writing, verifying, done） |
| `data-retrieval-progress` | Dense/Sparse/Fused 命中数量 |
| `text-delta` | 答案的 token 片段 |
| `data-citation-snapshot` | 前 5 条引用 |
| `finish` | 流结束 |

**LLM 配置**：
- Router/Rewriter/Decomposer/Verifier：`qwen-turbo`，temperature 0.1-0.3，超时 15s
- Writer：默认模型，temperature 0.5，支持流式

## 8. 完整请求-响应流程（RAG 模式）

```
1. Client → POST /chat/stream
   Headers: Authorization: Bearer <token>
   Body: StreamChatDto { sessionId, chatMode: 'rag', message, selectedKbIds }

2. ChatController.streamChat()
   - @UseGuards(AuthGuard, StreamRateLimitGuard)
   - @Auth() → 从 JWT 提取 userId
   - @SkipResponseTransform()
   - 调用 chatStreamService.streamChat(userId, dto)

3. ChatStreamService.streamChat()
   a. chatSessionService.assertSessionOwnership(userId, sessionId)
      → 无效则抛出 CONVERSATION_NOT_FOUND 或 CONVERSATION_UNAUTHORIZED

   b. kbPermissionService.authorizeMany(userId, selectedKbIds, 'ask')
      → 返回 permContexts 和 resolvedKbIds

   c. chatMessageService.createUserMessage() → 持久化用户消息

   d. chatMessageService.createAssistantPlaceholder() → 创建流式占位符

   e. orchestrator.streamRun(runCtx, { onFinish, onError })
      - 创建 AI SDK ReadableStream<UIMessageChunk>

4. MultiAgentOrchestratorService.streamRun()
   a. agentTraceService.createRun(runCtx)
      → 创建 b_agent_runs 记录

   b. 构建预生成 StateGraph，节点：
      route → rewrite/skip_rewrite → decompose/skip_decompose → retrieve_prep → tools → relevance_check → [重试循环]

   c. 执行图，发送状态事件：
      - data-agent-status: { phase: 'planning'|'retrieving'|'verifying'|'writing'|'done', detail }
      - data-retrieval-progress: { denseCount, sparseCount, fusedCount }

   d. 通过 chatModelService.createModel() 流式输出答案：
      - 为每个 token 块发送 text-delta 事件

   e. 对于复杂查询（compare_analysis, research）：
      - 并行运行 factCheckNode() + completenessCheckNode()

   f. 发送 data-citation-snapshot，包含前 5 条引用

   g. 调用 onFinish 回调
      → CitationService.createCitations() + finalizeAssistantMessage()

   h. writer.write({ type: 'finish', finishReason: 'stop' })

5. pipeUIMessageStreamToResponse({ response, stream })
   → 将 SSE 流写入 HTTP 响应

6. Client 收到的 SSE 事件流：
   - { type: 'data-agent-status', data: { type: 'agent-status', phase, detail } }
   - { type: 'data-retrieval-progress', data: { type: 'retrieval-progress', ... } }
   - { type: 'text-delta', id: 'rag-msg-1', delta: 'token text' }
   - { type: 'data-citation-snapshot', data: { type: 'citation-snapshot', citations: [...] } }
   - { type: 'finish', finishReason: 'stop' }
```

## 10. 关键设计模式

### 10.1 StateGraph 编排
使用 LangGraph 的 `StateGraph` 与 `Annotation.Root()` 实现类型安全的状态管理。

### 10.2 结构化输出
所有智能体节点使用 `model.withStructuredOutput(Schema, { method: 'jsonMode' })` 获取 LLM 响应。

### 10.3 流式处理
使用 `@ai-sdk/langchain` 的 `toUIMessageStream()` 和 `createUIMessageStream()` 实现标准流式协议。

### 10.4 降级策略
当 LLM 调用失败时进行优雅降级（如：跳过重写使用原始查询，跳过分解等）。

### 10.5 引用追踪
重排后的命中结果以 `b_chat_message_citations` 形式持久化，包含引用、分数和排序。

### 10.6 可追溯性
每次智能体运行都在 `b_agent_runs` 和 `b_agent_steps` 中追踪，用于调试和数据分析。
