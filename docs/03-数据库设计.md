# Linsor AI 数据库设计

系统使用 MySQL 8 和 Prisma。本文只描述数据域和关键关系，不复制全部字段；字段、索引和约束以 `apps/server/prisma/schema.prisma` 与 migrations 为准。

## 命名规则

- `b_`：前台业务表。
- `sys_`：系统管理与基础配置表。
- 主键使用数据库生成的 BigInt。
- 时间字段统一保存创建、更新或业务时间。
- 状态和角色由应用层校验，关键组合关系使用唯一索引约束。

## 当前模型

### 用户与认证

- `b_users`
- `b_user_sessions`
- `sys_email_codes`
- `sys_admins`
- `sys_admin_sessions`

用户会话与管理员会话相互独立。Refresh Token 会话用于轮换、注销和失效管理。

### 模型与配额

- `sys_model_configs`
- `b_user_model_configs`
- `b_user_daily_quotas`

系统模型配置由管理员维护；用户可保存自己的模型配置。敏感密钥必须加密存储。

### 知识库与协作

- `b_knowledge_bases`
- `b_kb_members`
- `b_kb_invitations`

知识库所有者记录在知识库表，成员表只保存加入成员。邀请记录负责邀请码、目标角色和有效状态。

### 文档、上传与处理

- `b_documents`
- `b_upload_sessions`
- `b_upload_chunks`
- `b_document_chunks`
- `b_document_processing_tasks`

上传会话与分片支持断点续传和完成校验。文档通过 `processing_version` 隔离重解析版本；Chunk 保存结构、位置、层级、索引标识和扩展元数据；处理任务记录阶段、尝试次数、心跳和错误。

### 对话与评估

- `b_chat_sessions`
- `b_chat_messages`
- `b_chat_message_citations`
- `b_agent_runs`
- `b_agent_steps`

会话包含多条用户和助手消息。引用单独关联助手消息及文档 Chunk。Agent Run 保存一次编排执行，步骤记录用于追踪节点和工具调用；评估结果写入 Run 元数据。

### 系统治理

- `sys_audit_logs`
- `sys_dict_type`
- `sys_dict_item`

审计日志记录关键后台操作；字典表维护可配置的系统枚举和值。

## 跨存储一致性

- MySQL 保存业务事实和索引引用。
- Qdrant point 通过文档和 Chunk 标识关联 MySQL。
- Elasticsearch document 通过相同标识关联 MySQL。
- 删除文档时同步清理 Qdrant 和 Elasticsearch。
- 重解析先递增版本并清理旧索引，再生成新 Chunk 和索引。
- 旧任务必须在写入前校验 `processing_version`。

## 变更规则

1. 先修改 Prisma Schema。
2. 创建并审查 migration。
3. 更新依赖该字段的 DTO、Service 和测试。
4. 涉及索引结构时同步处理 Qdrant/Elasticsearch 重建或兼容。
5. 只在数据域和关键关系发生变化时更新本文档。
