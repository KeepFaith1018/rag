## 核心结论

本系统检索链路优秀（三层粒度、熵加权 RRF、质量乘数均为业内独有），但缺少 Agentic RAG 的标志性特征——**自校正闭环**。同时存在 6 个 P0 级缺陷、8 个 P1 级质量问题。

---

## 四阶段总览

| 阶段 | 主题 | 工期 | 核心目标 |
|------|------|------|---------|
| **一** | 修复 + 性能 | 1-2 天 | 消缺 + 检索延迟 -40% |
| **二** | Agentic RAG 闭环 | 3-5 天 | 自校正闭环（检索重试 + 质量校验） |
| **三** | 代码质量提升 | 3-5 天 | 消除重复、统一工具函数 |
| **四** | 长期增强 | 后续 | HyDE / MMR / Checkpointing |

---

## 第一阶段：修复 + 性能（7 项）

| # | 项目 | 优先级 | 预期收益 |
|---|------|--------|---------|
| 1.1 | Dense/Sparse 检索并行化 | P0 | 检索延迟 -40% |
| 1.2 | RetrievalTraceService 内存泄漏修复 | P0 | 避免 OOM |
| 1.3 | Fusion O(n*m) → O(1) | P1 | 融合延迟 -50% |
| 1.4 | Context 截断保护 | P0 | 避免 LLM 调用失败 |
| 1.5 | AbortSignal 完善 | P0 | 避免浪费 API 调用 |
| 1.6 | AgentTrace completeRun/failRun | P1 | 修复追踪数据 |
| 1.7 | onFinish 回调并行化 | P1 | 后处理延迟 -60% |

## 第二阶段：Agentic RAG 闭环（4 项）

| # | 项目 | 说明 |
|---|------|------|
| 2.1 | 启用 Relevance Check 节点 | 检索后评估相关性，不相关则重新改写 |
| 2.2 | 检索重试环 | audit insufficient → rewrite_fallback → retry |
| 2.3 | 启用 Fact Check 节点 | 逐句校验，高风险触发修正 |
| 2.4 | 启用 Completeness Check 节点 | 缺失维度触发补充检索 |

## 第三阶段：代码质量（3 项）

| # | 项目 | 新建/修改文件数 |
|---|------|:---:|
| 3.1 | 提取共享工具函数 | 4 新文件 |
| 3.2 | 清理重复/废弃代码 | ~5 文件 |
| 3.3 | 补充健壮性（超时/日志/类型） | ~3 文件 |

## 第四阶段：长期增强

HyDE 检索增强、Dual Rewriting、MMR 多样性 Rerank、检索进度实时推送、LangGraph Checkpointing、LangSmith 集成。
