# 基于信息检索增强的知识库问答系统 - 需求分析报告

## 1. 项目背景与目标

本项目旨在解决个人或小团队在知识管理、检索和复用过程中遇到的效率低下、信息碎片化等痛点。通过结合大语言模型（LLM）和检索增强生成（RAG）技术，构建一个智能化的私有知识库问答系统。
除了个人的知识沉淀，系统还支持多人协作、知识共享，实现从“个人知识助手”向“团队知识引擎”的扩展。

## 2. 核心用户角色

本系统分为前台业务系统与后台管理系统，两者的角色与权限体系（RBAC）完全独立且互不兼容。

### 2.1 前台系统角色

- **前台系统用户**：所有注册使用知识库的用户。在个人的私有知识库中拥有绝对控制权。
- **共享知识库协作角色**（仅在共享知识库中区分）：
  - **创建者（owner）**：发起共享的人，可管理知识库设置、成员、文档及公开策略。
  - **管理者（manager）**：受邀加入的高级协作者，可管理成员以及全部文档，但不拥有知识库所有权。
  - **协作者（collaborator）**：可上传文档，并且仅能管理自己上传的文件。
  - **成员（member）**：默认加入角色，只读使用共享知识库内容。
- **共享知识库公开访问者**（仅当共享知识库开启开源时存在）：
  - **普通登录用户（publicVisitor）**：可搜索、查看并使用已开源的共享知识库进行问答；是否允许下载文件由知识库配置决定。公开访问者不属于成员体系。

### 2.2 后台管理系统角色（独立RBAC）

- **系统管理员**：负责整个平台的宏观配置、用户治理及资源监控，拥有后台管理系统的最高权限。

## 3. 详细功能需求分解

### 3.1 基础系统功能模块

- **用户鉴权与账号管理**
  - **注册/登录**：支持账号密码登录、邮箱验证码注册与登录。
  - **密码找回**：通过邮箱验证码重置密码。
  - **个人中心**：修改基本信息、头像、密码等。
- **个性化与系统设置**
  - **系统换肤**：支持明暗模式（Light/Dark Mode）一键切换。
  - **主题色切换**：提供多种主题强调色供用户自定义，提升系统UI/UX体验。

### 3.2 知识库管理模块（核心）

- **知识库分类与隔离**
  - **私有知识库**：用户个人专属，数据完全私有，其他任何人不可见，也不可被搜索。
  - **共享知识库**：支持邀请成员协作。共享知识库可进一步配置是否**开源**：
    - **未开源共享知识库**：仅创建者和已加入成员可见，不可被搜索。
    - **已开源共享知识库**：登录用户可搜索、查看和使用；是否允许下载知识库内文件由知识库配置决定。
- **文档管理与解析**
  - **多格式支持**：支持 TXT、Markdown、PDF、Word 等常见文档格式的上传。
  - **数据分块与向量化**：上传文档后，系统自动进行文本切片（Chunking）并调用嵌入模型（Embedding）存入向量数据库。
  - **文件权限控制（针对共享知识库）**：
    - `owner`：可管理知识库设置、成员及全部文件。
    - `manager`：可管理成员，并可上传、删除、重解析全部文件。
    - `collaborator`：可上传文件，但仅可删除和重解析自己上传的文件。
    - `member`：可读、可下载、可问答，不可上传和管理文件。
    - `publicVisitor`：可搜索、可查看、可问答；是否允许下载源文件由知识库创建者配置。
  - **文档管理基础操作**：支持查看已上传文档列表、删除文档、手动触发重新解析（受权限控制）。

### 3.3 检索增强问答模块（核心与扩展）

- **智能对话界面**
  - 类似 ChatGPT 的对话界面，支持上下文多轮对话。
  - 用户可选择特定的知识库进行提问，系统基于该知识库内容进行回答。
  - 已开源的共享知识库支持被登录用户搜索发现并直接发起问答；未开源的共享知识库仅限已加入成员在相应权限范围内使用。
- **溯源与引用**
  - 大模型回答时，必须附带信息来源（引用的具体文档名称及相关段落），保证回答的准确性和可信度。
- **自定义模型配置与防盗刷机制**
  - **私有模型配置**：用户可自行填入自己的第三方大模型 API Key，系统优先使用用户自己的 Key 进行调用。
  - **公有模型限制（防盗刷）**：如果用户未配置自己的 Key，则使用系统管理员在后台配置的“全局默认公有大模型”。为了防止管理员的 Token 被恶意盗刷，系统对公有模型调用实施**严格的额度限制（Rate Limiting & Quota）**：
    - **单用户每日调用次数限制**（如：每人每天限对话 50 次）。
    - **单用户 Token 总量限制**（达到阈值后强制要求用户配置自己的 API Key 才可继续使用）。
  - **参数调整**：支持调整 Temperature（发散度）、Max Tokens 等参数。
- **工具调用（Tool Calling）与联网搜索（需求扩展）**
  - **系统工具调用**：扩展大模型能力，允许模型根据用户意图调用外部工具，打破仅限知识库问答的局限。
  - **联网搜索增强**：引入联网搜索（Web Search）功能。当本地知识库中缺乏相关信息，或用户需要获取最新实时资讯时，系统可触发联网搜索，将搜索结果作为补充上下文供大模型总结，实现“本地私有知识 + 广域互联网”的双重增强。

### 3.4 后台管理系统（已确认需求）

- **独立 RBAC 系统**：后台管理拥有独立的角色权限控制体系，与前台隔离。
- **用户管理与统计**：查看全站用户列表、统计活跃度等，支持对违规用户进行**封禁**操作。
- **公有模型配额管理**：
  - 配置系统的默认全局大模型 API Key。
  - **设置与调整普通用户使用公有模型时的免费对话次数和 Token 配额限制**。
- **知识库监控（隐私保护机制）**：
  - **监控范围**：为保护个人隐私，后台**仅限监控“共享知识库”**；私有知识库对后台管理员不可见/不可干预。
  - **监控指标**：统计共享知识库的数量、文档数量、Token 用量、公开访问热度等。
  - **违规处理**：支持对存在违规内容的共享知识库进行**封禁**。
- **系统全局配置**：配置系统的发件邮箱（用于验证码）、系统通用模型配置等。

### 3.5 部署与分发需求（已确认需求）

- **私有化部署支持**：提供 Docker 和 Docker Compose 编排文件，支持用户一键将整个系统（前后端、数据库、向量库）部署在自己的本地服务器或云服务器上，保证数据绝对隐私。

## 4. 非功能性需求（已确认）

- **安全性**：密码加密存储（如 bcrypt），接口需有鉴权机制（JWT），防止越权访问。
- **性能要求**：文档解析和向量化过程应采用异步处理，避免阻塞主线程；问答接口支持流式输出（SSE/WebSocket），提升用户等待体验。
- **响应式设计**：前端页面需适配不同尺寸屏幕，至少保证 PC 端和 Pad 端的良好体验。
