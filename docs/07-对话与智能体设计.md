# Linsor AI 对话与智能体设计

## 对话模式

- `chat`：直接使用选定模型生成回答，不检索知识库。
- `rag`：进入 LangGraph 编排，检索用户选定且有权访问的知识库。

每次请求单独解析模型配置和知识库范围。会话保存连续消息，上下文管理服务根据 token 预算构建历史。

## 当前 RAG 图

```text
START
  → route
  → [writer | decompose/rewrite]
  → retrieve_prep
  → tools
  → relevance_check
  → [writer | audit]
  → [writer | rewrite_fallback]
  → writer
  → END
```

节点职责：

| 节点 | 职责 |
|---|---|
| `route` | 判断是否检索以及查询处理策略 |
| `decompose` | 将复杂问题拆成子问题 |
| `rewrite` | 生成检索查询与关键词 |
| `retrieve_prep` | 切换检索阶段 |
| `tools` | 执行知识库检索 |
| `relevance_check` | 判断候选内容与问题的相关性 |
| `audit` | 审计检索充分性并决定后续路径 |
| `rewrite_fallback` | 调整查询后重试 |
| `writer` | 基于上下文流式生成最终回答 |

图通过重试次数和条件边保证终止，不允许无限循环。

## AG-UI SSE

流式接口为 `POST /api/chat/stream`。主要事件：

- 运行：`RUN_STARTED`、`RUN_FINISHED`、`RUN_ERROR`
- 步骤：`STEP_STARTED`、`STEP_FINISHED`
- 工具：`TOOL_CALL_START`、`TOOL_CALL_RESULT`
- 文本：`TEXT_MESSAGE_START`、`TEXT_MESSAGE_CONTENT`、`TEXT_MESSAGE_END`
- 校验：`VALIDATION_STARTED`、`VALIDATION_COMPLETED`

事件以原生 SSE `data: <json>` 发送。前后端必须以共享语义维护事件，不得在 UI 组件中直接猜测原始数据结构。

## 持久化

- `b_chat_sessions`：会话。
- `b_chat_messages`：用户和助手消息。
- `b_chat_message_citations`：助手消息引用。
- `b_agent_runs`：一次 Agent 执行及元数据。
- `b_agent_steps`：步骤、工具和耗时追踪。

主回答和引用在用户请求链路中保存；质量评估结果允许稍后追加到 Agent Run。

## 离线评估

回答完成后通过 BullMQ 异步评估：

- Faithfulness：回答是否受上下文支持。
- Answer Relevancy：回答是否切题。
- Context Recall：上下文是否覆盖回答所需信息。

评估失败不影响主回答，但必须记录失败原因。

## 降级与安全

- 用户模型配置不可用时可回退系统模型，并通过事件告知前端。
- 检索不足时允许重写、重试或 Web Search；不得伪造知识库引用。
- 客户端取消请求后停止继续向连接写入。
- Prompt 和模型输出不能替代后端权限校验。
- Trace 中不得持久化明文密钥和不必要的敏感内容。
