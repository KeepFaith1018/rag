# Linsor AI 分片上传设计

## 目标

为大文件提供分片上传、断点续传、重复提交幂等、取消和秒传能力，并在文件完成后无缝进入文档处理队列。

## 接口流程

```text
初始化上传
  → 上传缺失分片
  → 查询状态/恢复
  → 完成合并
  → 创建文档
  → 提交处理任务
```

后端接口位于知识库资源下：

- `POST .../uploads/init`
- `POST .../uploads/:uploadId/chunks`
- `GET .../uploads/:uploadId/status`
- `POST .../uploads/:uploadId/complete`
- `DELETE .../uploads/:uploadId`

所有操作要求当前用户具备知识库上传权限。

## 前端职责

- Web Worker 计算完整文件 SHA-256，避免阻塞页面。
- 按约定大小切分文件。
- 控制并发、重试和暂停。
- 根据后端状态只上传缺失分片。
- 展示哈希、上传、合并和处理阶段进度。

## 后端职责

- 创建上传会话并校验文件元数据。
- 根据文件哈希判断是否满足秒传条件。
- 校验上传会话归属、状态、分片序号和内容。
- 幂等保存分片并维护已上传数量。
- 完成时确认全部分片存在，按顺序合并并校验哈希。
- 在事务边界内创建文档记录并提交处理任务。
- 取消或过期后清理临时分片。

## 幂等与一致性

- 同一会话的同一分片重复上传不得重复计数。
- `complete` 重复调用应返回已有结果或稳定状态。
- 合并前以实际分片记录为准，不只信任客户端计数。
- 文件哈希、总大小、分片数量和分片顺序必须一致。
- 文档创建成功但入队失败时，必须记录失败状态并允许恢复。

## 秒传

秒传只能复用当前用户有权访问且文件内容完整的已有资源。相同哈希不等于自动获得其他知识库文档权限；系统需要创建符合目标知识库归属的新文档关系或执行明确的复用策略。

## 安全

- 限制文件类型、单文件大小、分片大小和总分片数。
- 文件名只作为显示信息，不直接用于未净化的磁盘路径。
- 临时目录和最终路径必须位于受控存储根目录。
- 服务端重新计算或验证关键哈希。
- 定期清理过期、取消和失败会话的临时文件。
