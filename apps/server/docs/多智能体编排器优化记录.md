# 多智能体编排优化总结

**日期**: 2026-04-29（最后更新：2026-05-05）

## 优化背景

用户反馈流式多智能体编排存在两个核心问题：
1. 决策节点频繁超时（`Request timed out`），复杂查询需要 130s+
2. 前端与控制台日志不同步

## 优化内容

### P0: `withStructuredOutput` 切换到 `json_mode`

**根因**：LangChain `withStructuredOutput(Schema)` 默认发送 `response_format: json_schema` + `strict: true`，百炼平台对此支持不稳定，导致模型在嵌套 schema（如 Rewrite）时卡死或超时。

**修复**：5 个决策节点的 `withStructuredOutput` 全部加上 `{ method: 'json_mode' }` 参数，改为发送百炼原生支持的 `response_format: json_object`。

```typescript
// 修改前
model.withStructuredOutput(RoutedQueryPlanSchema)
// 修改后
model.withStructuredOutput(RoutedQueryPlanSchema, { method: 'json_mode' })
```

### P1.1: 决策节点使用快模型

6 个决策节点（route/rewrite/decompose/fact_check/completeness_check/relevance_check）从 `qwen3.6-plus` 切换为 `qwen-turbo`，决策任务无需强模型。生成回答的节点保留 `qwen3.6-plus`。

### P1.2: fact_check 与 completeness_check 并行

两个校验节点仅读取 state（`draftAnswer`、`rerankedHits`），互不依赖对方的输出。改用 `Promise.all` 并行执行，校验阶段耗时从 15s×2 → max(15s, 15s)。

### P2: 删除 LangGraph 死代码

`streamRun()` 实现后不再使用 LangGraph，移除了：
- `StateGraph`/`Annotation` 导入
- `AgentStateAnnotation` → 改为纯 TypeScript `interface AgentState`
- `run()` 方法（~200 行）
- `draftAnswerNode` 函数（已被 `model.stream()` 替代）
- `shouldRetryOrContinue`/`shouldReviseOrContinue`/`shouldSupplementOrFinalize`（LangGraph 边缘条件函数）
- `MAX_FALLBACK` 常量

**文件变化**: 1203 行 → 870 行

| 场景 | 优化前 | 优化后 |
|------|--------|--------|
| 简单查询 (fact_lookup) | 3 LLM 调用, ~10s | 2 LLM 调用, ~3-5s (route + generate) |

| 决策超时概率 | 高（json_schema 不兼容） | 低（json_mode 原生支持） |

## 保留的架构

`streamRun()` 使用 **LangGraph 管编排 + 独立流式生成** 的混合架构：

```
┌─── LangGraph 预生成图 ──────────────────────────────┐
│  route → rewrite → decompose → retrieve → relevance │
│     ↑                                    │          │
│     └───── retry loop ──────────────────┘          │
│  graph.stream() → 逐节点推送 data-agent-status      │
└────────────────────────────────────────────────────┘
                        ↓
┌─── 流式生成（独立于 graph）───┐
│  model.stream() → 逐 token 推送 text-delta        │
└──────────────────────────────┘
                        ↓
┌─── 质量校验（仅复杂查询）───┐
│  Promise.all(fact_check, completeness_check)        │
│  逐校验结果推送 data-agent-status                   │
└──────────────────────────┘
```

LangGraph 负责 branch/loop 逻辑（route→rewrite, relevance→retry），流式生成脱离 graph 实现 token 级实时输出。

## SSE 流式输出协议

后端使用 `createUIMessageStream` + `pipeUIMessageStreamToResponse` 将流转换为 SSE 格式：

```
data: {"type": "text-delta", "id": "rag-msg-1", "delta": "文本内容"}\n\n
data: {"type": "data-agent-status", "data": {"type": "agent-status", "phase": "planning", "label": "...", "detail": "..."}}\n\n
data: {"type": "data-retrieval-progress", "data": {"type": "retrieval-progress", "denseCount": 5, "sparseCount": 3, "fusedCount": 5}}\n\n
data: {"type": "data-citation-snapshot", "data": {"type": "citation-snapshot", "citations": [...]}}\n\n
data: {"type": "finish", "finishReason": "stop"}\n\n
data: [DONE]\n\n
```

### 事件类型列表

| type | 结构 | 用途 |
|------|------|------|
| `text-delta` | `{delta: string}` | AI 回复文本增量 |
| `data-agent-status` | `{phase, label, detail}` | Agent 工作流阶段 |
| `data-retrieval-progress` | `{denseCount, sparseCount, fusedCount}` | 检索进度 |
| `data-citation-snapshot` | `{citations: [...]}` | 引用快照 |
| `data-agent-warning` | `{code, message}` | Agent 警告 |
| `finish` | `{finishReason}` | 流结束 |
| `[DONE]` | - | SSE 连接结束 |

### Agent Phase 流转

`planning` → `retrieving` → `verifying` → `writing` → `done`

### 前端解析（2026-05-05 修复）

前端 `useAgentChat.ts` 使用 `parseSSEData` 函数正确解析 SSE 行：

```typescript
function parseSSEData(line: string): { type: string; data: Record<string, unknown> } | null {
  if (!line.startsWith('data: ')) return null;
  const json = line.slice(6); // 去掉 "data: " 前缀
  if (json === '[DONE]') return { type: '[DONE]', data: {} };
  try {
    const obj = JSON.parse(json) as Record<string, unknown>;
    return { type: obj.type as string, data: obj };
  } catch {
    return null;
  }
}
```

## 取消请求功能

前端通过 `AbortController` 实现取消请求：

1. 用户点击取消按钮，调用 `abort()`
2. `AbortController.abort()` 中断 fetch 请求
3. 后端检测到 AbortError，跳过消息持久化
4. 前端显示"请求已取消"状态

```typescript
// useAgentChat.ts
function abort(): void {
  if (abortController.value) {
    abortController.value.abort();
    chatStore.addWarning({
      type: 'agent-warning',
      code: 'USER_CANCELLED',
      message: '用户取消了请求',
    });
  }
}
```
